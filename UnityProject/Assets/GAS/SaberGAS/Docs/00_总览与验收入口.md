# Saber.GAS 总览与验收入口

## 1. 当前目标

`Saber.GAS` 的目标不是做一个“只服务于当前 FFD 回合制战斗”的二次封装，而是抽出一套：

- 完全独立的能力系统核心
- 不依赖旧 `NewBattle` 运行时
- 不把回合制写死进核心
- 支持 RTS / MOBA / 回合制 / Action-RPG 共享同一套逻辑层
- 从设计初期就考虑网络同步、预测、快照、回放

当前这套实现已经不是首版骨架，而是具备以下闭环的可用系统：

- 独立程序集
- 确定性数值
- 属性 / 资源 / Tag / Effect / Ability 基础模型
- `Attempt -> Block -> Impact -> Resolve` 行动流水线
- `Instant / Cast / Channeled / Passive` 基础能力生命周期
- 持续效果、叠层、周期触发、移除
- 命令缓冲、快照、恢复、重放宿主
- 面向 FastCloner 的深拷贝接点

## 4. 验收重点

你回来验收时，建议优先看下面这些点：

### 4.1 架构边界

- 是否仍然依赖旧 `NewBattle` 运行时类型
- 是否把回合制流程写死进核心
- 是否仍然用 `float` / `double` 作为战斗主数值

### 4.2 逻辑完整度

- 是否有显式的行动尝试对象
- 是否有结构化阻断结果
- 是否先生成 impact，再统一 resolve
- 是否支持长期技能实例而不只是瞬时释放

### 4.3 网络友好度

- 是否存在命令缓冲
- 是否存在快照捕获与恢复
- 是否能从某个 Tick 恢复后重放命令
- 是否把深拷贝实现留在接口边界而不是写死

## 5. 当前刻意留空的部分

下面这些不是漏做，而是有意留给后续接入层：

- Unity Inspector / ScriptableObject authoring
- 具体 Json 实现
- FastCloner 具体实现
- 投射物 / 地面区域实体 / UI / 特效 / 镜头
- 旧资产自动迁移器

它们之所以没在本轮一起落地，是因为当前优先级是先把“通用逻辑内核”真正做完整。
