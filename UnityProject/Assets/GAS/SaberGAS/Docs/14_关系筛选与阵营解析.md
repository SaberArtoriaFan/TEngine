# 14. 关系筛选与阵营解析

这次重构后，`Saber.GAS` 的关系判断分成了两层：

- `CombatActorRelationFlags`
  用来表达“我要匹配什么关系”
- `ICombatActorRelationResolver`
  用来定义“两个 Actor 实际是什么关系”

这样 Core 不再直接把 `TeamId` 相等解释成友军、`TeamId` 不等解释成敌军。

## 1. `CombatActorRelationFlags`

代码位置：

- `Runtime/Core/Runtime/CombatContracts.cs`

它是一个 `[Flags]` 枚举，支持组合：

- `Self`
- `Ally`
- `Enemy`
- `Neutral`
- `Other`
- `Any`

例如：

```csharp
var relation = CombatActorRelationFlags.Ally | CombatActorRelationFlags.Neutral;
```

表示“允许友军或中立”。

## 2. Trigger 如何使用

`TriggerDefinition` 现在的这些字段都使用 `CombatActorRelationFlags`：

- `RelationFilter`
- `TargetRelationFilter`
- `InstigatorRelationFilter`

例如：

```csharp
var trigger = new TriggerDefinition(new TriggerId("Trigger.Example.Observer"))
{
    CollectionMode = TriggerCollectionMode.ObserveTarget,
    TargetRelationFilter = CombatActorRelationFlags.Ally | CombatActorRelationFlags.Neutral,
    InstigatorRelationFilter = CombatActorRelationFlags.Enemy,
};
```

这表示：

- 我观察目标
- 目标必须是我的友军或中立
- 施加者必须是我的敌人

## 3. 技能目标筛选如何使用

`AbilityTargetFlags` 仍然是目标输入层的 Flags，但现在已经补了 `Neutral`：

- `Self`
- `Ally`
- `Enemy`
- `Neutral`
- `Dead`
- `Alive`
- `Point`

Runtime 在校验技能目标时，会先把这些关系 Flags 映射成 `CombatActorRelationFlags`，再交给关系解析器判断。

所以技能目标也不再直接依赖 `TeamId` 比较。

## 4. `ICombatActorRelationResolver`

代码位置：

- `Runtime/Core/Runtime/CombatContracts.cs`

接口定义如下：

```csharp
public interface ICombatActorRelationResolver
{
    CombatActorRelationFlags ResolveRelation(
        CombatWorldState worldState,
        CombatActorState sourceActor,
        CombatActorState targetActor);
}
```

核心思想是：

- Core 只负责问“这两者是什么关系”
- 业务层负责回答“为什么是这个关系”

## 5. Core 回退实现

`Saber.GAS` Core 现在只提供 `FallbackCombatActorRelationResolver` 作为兜底：

- 同一个 Actor -> `Self`
- 其他任意 Actor -> `Neutral`

注意：

- 这只是 Core 的保底行为
- 它不表达真实阵营
- 它的作用只是让 Runtime 在缺少业务接线时仍可运行

## 6. RTS 默认实现

`Saber.GAS.RTS` 中提供了 `RtsTeamRelationResolver`：

- 同一个 Actor -> `Self`
- 任一方 `TeamId.Empty` -> `Neutral`
- `TeamId` 相同 -> `Ally`
- 其他情况 -> `Enemy`

这类逻辑已经不再放在 `Saber.GAS` Core 中，而是作为 RTS 扩展程序集的一部分存在。

## 7. 业务层自定义示例

例如你可以这样定义一套更复杂的关系：

```csharp
public sealed class MyGameRelationResolver : ICombatActorRelationResolver
{
    public CombatActorRelationFlags ResolveRelation(
        CombatWorldState worldState,
        CombatActorState sourceActor,
        CombatActorState targetActor)
    {
        if (sourceActor == null || targetActor == null)
        {
            return CombatActorRelationFlags.None;
        }

        if (sourceActor.ActorId == targetActor.ActorId)
        {
            return CombatActorRelationFlags.Self;
        }

        if (IsTemporaryAlly(sourceActor, targetActor))
        {
            return CombatActorRelationFlags.Ally | CombatActorRelationFlags.Other;
        }

        if (IsNeutralCamp(targetActor))
        {
            return CombatActorRelationFlags.Neutral | CombatActorRelationFlags.Other;
        }

        return CombatActorRelationFlags.Enemy | CombatActorRelationFlags.Other;
    }
}
```

然后在 Runtime 创建时注入：

```csharp
var options = new CombatRuntimeOptions
{
    RelationResolver = new MyGameRelationResolver(),
};

var runtime = new CombatRuntime(worldState, options);
```

如果你走 RTS 默认装配，也可以直接这样接：

```csharp
var pack = new RtsCombatRuntimeModulePack();
var options = pack.CreateRuntimeOptions();
var runtime = new CombatRuntime(worldState, options);
```

## 8. 现在被统一接管的地方

当前这层关系解析已经接入：

- Trigger 的 `TargetRelationFilter`
- Trigger 的 `InstigatorRelationFilter`
- Trigger 的兼容字段 `RelationFilter`
- 技能目标合法性校验
- `OnAllyDeath` 这类依赖友军判断的事件派发

也就是说，后续你如果要扩“友军死亡狂暴”“中立受击触发”“临时盟友保护”这类内容，优先改的是业务层 `RelationResolver`，而不是回头改 Core。
