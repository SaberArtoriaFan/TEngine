# 标准战斗语义层使用说明

## 1. 最基础的接线

如果要在项目里启用标准战斗语义层，最少需要准备三样东西：

- `CombatSemanticCatalog`
- `CombatSemanticModule`
- `CombatSemanticBuilder`

示例：

```csharp
var catalog = new CombatSemanticCatalog();
var semanticModule = new CombatSemanticModule(catalog);
var semanticBuilder = new CombatSemanticBuilder(catalog);

var runtimeOptions = new CombatRuntimeOptions();
runtimeOptions.RuleModules.Add(semanticModule);

var cloneProvider = new FastClonerDeepCloneProvider(
    new ICombatExtensionCloneHandler[] { semanticModule });
```

这样接完之后：

- `CombatRuntime` 会自动查询 `semanticModule`
- 快照和回滚会通过 `cloneProvider` 带上语义扩展状态

## 2. 伤害

```csharp
var damageEffect = semanticBuilder.CreateDamageEffect(
    new EffectId("Effect.Skill.Fireball.Damage"),
    healthResourceId,
    120);
```

这个定义会自动附加：

- `Effect.Semantic.Damage`
- `Impact.Damage`

如果你需要纯粹伤害：

```csharp
var pureDamage = semanticBuilder.CreateDamageEffect(
    new EffectId("Effect.Skill.Execution.PureDamage"),
    healthResourceId,
    300,
    DamageSemanticKind.Pure);
```

纯粹伤害默认不会被普通伤害免疫拦掉，只会被 `Immunity.All` 拦掉。

## 3. 周期伤害

```csharp
var burn = semanticBuilder.CreatePeriodicDamageEffect(
    new EffectId("Effect.Skill.Burn"),
    healthResourceId,
    magnitudePerTick: 18,
    periodTicks: 15,
    durationTicks: 90);
```

这个定义适合：

- 灼烧
- 中毒
- 流血
- 光环灼伤

## 4. 治疗

```csharp
var heal = semanticBuilder.CreateHealEffect(
    new EffectId("Effect.Skill.Heal"),
    healthResourceId,
    80);
```

如果你想表达吸血或汲取类效果，也可以先用：

```csharp
var drainHeal = semanticBuilder.CreateHealEffect(
    new EffectId("Effect.Skill.Drain.Heal"),
    healthResourceId,
    40,
    HealSemanticKind.Drain);
```

当前这层主要帮你统一标签和构造入口。  
如果以后你要做“治疗衰减”“禁止治疗”“吸血转护盾”这类更复杂语义，建议继续扩 `CombatSemanticModule`。

## 5. 护盾

```csharp
var barrier = semanticBuilder.CreateShieldEffect(
    new EffectId("Effect.Skill.Barrier"),
    healthResourceId,
    capacity: 180,
    durationTicks: 120);
```

这个定义会做三件事：

1. 给效果加上 `Effect.Semantic.Shield`
2. 给目标加上 `State.Semantic.Shield.Active`
3. 在效果扩展里附加 `CombatSemanticEffectExtension`，由 `CombatSemanticModule` 在运行时生成护盾状态

也就是说，护盾现在已经不在 Core 里硬编码了，而是标准语义层自己解释。

## 6. 控制

```csharp
var stun = semanticBuilder.CreateControlEffect(
    new EffectId("Effect.Skill.Stun"),
    ControlSemanticKind.Stun,
    durationTicks: 45);
```

控制效果会自动附加：

- `Effect.Semantic.Control`
- `State.Semantic.Control.Any`
- 对应的具体控制状态标签

例如眩晕会附加：

- `State.Semantic.Control.Stun`

这些标签会被 `CombatSemanticModule` 用来阻断能力尝试。

## 7. 驱散

```csharp
var cleanse = semanticBuilder.CreateDispelEffect(
    new EffectId("Effect.Skill.Cleanse"),
    DispelSemanticKind.Cleanse,
    removeNegative: true);
```

驱散本身仍然通过 `RemovedTargetEffectTags` 落地，但是否允许落地由语义层模块判断：

- 如果目标有 `Immunity.Dispel`
- 那么这个驱散效果会被拦掉

## 8. 免疫

```csharp
var controlImmune = semanticBuilder.CreateImmunityEffect(
    new EffectId("Effect.Skill.ControlWard"),
    ImmunitySemanticKind.Control,
    durationTicks: 90);
```

当前标准免疫分成：

- `Damage`
- `Control`
- `Dispel`
- `All`

运行时会自动处理：

- 控制免疫阻断控制效果落地
- 驱散免疫阻断驱散效果落地
- 伤害免疫阻断标准伤害资源变化

## 9. 什么时候该继续扩模块

以下这些需求，如果只是配置 Builder 还不够，就应该继续扩 `CombatSemanticModule`：

- 治疗禁制
- 吸血
- 伤害反弹
- 伤害分担
- 伤害改写
- 破盾后触发额外事件
- 指定伤害类型免疫

判断标准很简单：

- 如果只是“构造一个标准定义”，扩 `CombatSemanticBuilder`
- 如果是“运行时结算规则要变”，扩 `CombatSemanticModule`
- 如果发现必须回头改 `CombatRuntime`，优先先想一遍是否应该补 `ICombatRuleModule` 的能力

## 10. 现阶段的边界

这层已经覆盖了最常见的标准机制入口，但还不是最终形态。

当前还没有完全标准化的一些高阶语义包括：

- 吸血
- 反弹
- 伤害转治疗
- 护盾优先级
- 特定来源过滤
- 指定队友代伤
- 治疗衰减

这些不是不能做，而是更适合作为下一轮标准语义扩展继续补进 `CombatSemanticModule`。
